# Same five-stage family, learner-appropriate teaching

Read pinned family source_locale/locales: es for English study, en otherwise. Eleven final learners exclude study; ten translations exclude source/study. Source is real learner teaching. Follow AGENTS.md's catalogue-first historical retrieval: scan all compact topics/objectives, then inspect original source plus assigned-locale historical teaching/quiz sections/notes relevant to inherited rules, terminology, contrasts, links or findings. Other locales are read only for concrete cross-locale issues. Each record pins its source; future/planning and later own-stage content never supplies earlier teaching. Complete history remains stored and locally validated, not sent to the provider and not required to be exhaustively reread by every role. Current five-stage source/candidate and item audits remain complete.

## Inspect → recover

Read all ten full five-stage candidates and adaptation notes before experts. Candidate is exactly `{"stages":[{"stage":0,"lesson_md":"...","quiz_md":"...","adaptation_notes":[]}, ...]}` with five ordered stages0–4, no omitted/duplicate/reordered members. Empty lesson_md is legal only for reviewed practice returns; all other teaching remains nonempty. One invalid stage rejects all adoption; compare full family invariant contract and actual learner-language completeness.

| State | Action |
| --- | --- |
| Completed unchanged | Resume reuses evidence; no paid call or expert-edit overwrite. |
| Publication interrupted | Resume verifies entire locale old/planned inventories before recovery; never edit journals. |
| Terminal completed candidate rejected | Retain and repair, rather than stop the family. Save corrected five-stage JSON separately; use `--lang CODE --repair-candidate PATH` when its unchanged completed-response preconditions hold. Otherwise use the offline full-tree reconstruction route below. |
| Failed/incomplete terminal with complete message item | Extract individual retained message items using `tools/reauthorize-translations.py --extract-retained CODE --run RUN --output PATH`. It writes draft evidence, not adoption or approval. A completed message inside a failed response is useful retained material, not permission to rewrite the terminal state or repurchase it. |
| Incomplete response, missing stage, exhausted authorized retries | Preserve fragments. Assign a bilingual editor to complete missing learner content from the approved source in a separate workspace, then validate/integrate all five members and obtain a different genuine reviewer. Missing learner text is a reconstruction task, not missing source input. No further Contactbox calls are implied. |
| Transient failure with remaining allowance | Authorized scheduler follows persisted due times and original four-attempt budget. Prospectively, verified unrecoverable provider max_output_tokens responses can retry within that same budget after at least30minutes, never repurchasing complete retained content. Existing nonretryable journals are not rewritten. |
| Source/approval drift | Freeze publication, preserve prior evidence, rereview genuine source corrections, then reconcile locales offline. Do not change inputs simply to reset an API budget. |
| Auth/billing/refusal, explicit cancellation, unknown ownership or missing source/evidence | Preserve evidence and report the precise operator-required blocker. Do not treat the reconstruction route as authorization to override a user stop, provider refusal, unpaid quota or ownership guard. |

Before any source correction, inventory each locale as published tree, complete candidate-only (including rejected completed responses), or incomplete/missing response. Freeze publication and reviewers; preserve the original request, raw response, candidate and journals. Repair retains raw provider output and requires original input/context/approval identity. Source/brief drift needs genuine source rereview and manual expert reconciliation of existing locale trees with fresh source/language reports; old journals remain historical, and changed hashes cannot be resumed or repaired automatically. For a complete candidate-only locale after genuine source rereview, an explicitly assigned expert may reconstruct all five current members offline from retained material into its owned locale tree, recording provenance and repairs in adaptation notes. Validate the complete current family contract and obtain a real new locale review; do not call stale repair/resume, edit old hashes or pretend the provider returned the repaired version. If incomplete material cannot be safely reconstructed, stop with the exact missing scope. No partial publication or paid resend is implied. Do not attempt a paid resend to bypass drift. Prompt fixes are prospective under authoring-tooling/ownership; never rewrite saved requests to masquerade as unchanged resume. A new authorization alone does not make changed inputs an unchanged retry.

## Offline reconstruction before review

Routine full-family scope includes this path when the source and its approvals are available and unchanged. It is ordinary assigned agent work, not a new Contactbox request or permission to select a different paid provider.

1. Inventory saved trees, all attempts/renewal scopes, candidate files and actual message-item evidence before purchasing anything. A terminal response can omit an earlier complete item; do not concatenate distinct output items into one JSON document. The extraction CLI is read-only with respect to original evidence and learner trees; its drafts and provenance need human-agent inspection.
Only salvage complete JSON-decoded stage units when their source/request provenance matches the current source and stage-level target/answer contract verifies. Truncated text is reference evidence, not an approved stage. Take practice/extend from the approved brief.extension, never provider notes. When hashes differ, establish actual unchanged source bytes or translate that unit anew from current approved source; do not assume equivalence from IDs.

2. Give one bilingual editor exclusive ownership of a separate `work/content-recovery/STUDY/BASE/LOCALE/ATTEMPT-EDITOR_SESSION/...` workspace outside the family tree and the complete approved source, relevant history/briefs and retained drafts. Preserve source/request hashes and record the editor's real session. They translate missing material, reconcile corrupted/partial text against the source and fix formatting; they must not perform blind byte substitutions or call derived text provider-authored. Source IDs, target facts, ordering, answers and practice policy remain exact.
3. Build a complete five-member candidate and validate it using `tools/validate-family.cjs --root ROOT --run RUN --locale CODE --candidate PATH`; compare its full family_contract with current source validation. No individual stage gets published as completed. If a locale already has partial/expert edits, snapshot their bytes in that external recovery workspace (never extra lesson.md/quiz.md copies inside the family, whose inventory is strict) and reconcile with them explicitly; never let API publication overwrite them. The coordinator controls final integration into the mutable owned locale tree after all checks. Original requests, failed terminal status, grants, counters and raw captures remain untouched. Candidate/notes must record retained versus newly authored provenance.
4. Run `family_cli check --run RUN --locale CODE` on the complete integrated tree. Assign a **different** genuine language-expert session for all-page/all-item review. A fallback writer cannot approve its own reconstruction; an existing unaffected current review may be reused only when the bound locale is unchanged. Neither extraction, translation nor validation is language approval.
5. Continue unaffected locales and ordinary family integration. A reconstructable missing stage, old API-budget exhaustion or failed terminal alone is not a family blocker. Apply pack-review's progress-aware repair limits; block only actual unresolved defects or required evidence/authorization failures.

## Ten full-family experts

1. End source-review team. Fill templates/assignment.md for each locale: exact family/run, all five ranks/briefs/literacy policies, capability/stage plan, catalogue pagination and independently selected relevant source/assigned-locale historical originals, per-stage eligible/planning keys, earlier own stages, exclusive tree/report paths and binding.
2. Create one team; await each of ten lesson-language-expert spawns with worktree:false. Each owns `<run>/<locale>/stage-0..4/` and assigned reports only after prior writers are quiescent. Spawning is not completion: collect actual results and stay in the coordinator loop until all workers finish or are explicitly stopped; never end with an awaiting-editors message. For interrupted reconstruction editors, allocate a fresh attempt/session workspace instead of replacing them in the same path. Preserve late outputs without trusting their attribution; integrate only after checks and separate review. No source/study-locale expert or nested worker. Failed spawn means missing review; initial coordinator triage is not a substitute.
3. Each expert audits every page/item and every question ID with stage-local status/rationale/answer/alternatives/teaching_page evidence in templates/family-review.json. They fix only own learner prose/markup/notes, not target facts or other locales. Ordinary substantive repairs—not just reconstruction—use pack-review's different-verifier rule: the coordinator dispatches a genuine separate session after writer quiescence, and accepts its fresh language:CODE report in place of the editor's approval, retaining the editor's attribution. Source-wide defects broadcast actual stage/page/question evidence.
4. Coordinator owns shared-findings, resolutions and all ten checked/fixed/not-applicable acknowledgments. Three source reviewers recheck source-wide corrections. Reactivate completed experts for concrete later findings; stopped experts need real new review, never invented acknowledgment.
5. Source/brief changes pause writers and require three fresh source reports plus reconciliation/review across all ten locales. One locale-member typo affects that language/final only. Do not restart or family-convert an old run to bypass budgets.
6. Validate all eleven five-stage trees, collect current reports, stop writers; pack-review handles final binding/report/publication. Report measured usage, not estimated USD as a settled bill.

A learner must solve each stage from that version and actually available teaching, without source-language reading or later-family knowledge. Check false friends, scripts/RTL/readings, source analogies, regional consistency, grading clues and accepted alternatives. No native/audio/accessibility claim without actual testing.

Agent/skill revisions load only after all workers stop and OpenCode restarts.
