# Review evidence, not confidence

Required family roles: pedagogical, assessment, format for full source; ten language:CODE excluding study/source; coordinator final. Fourteen family-wide reports cover all five stages, not fourteen per stage. AGENTS.md defines safety and the role prompt the lens. Validators check structure, not truth, expertise or actual independent inspection.

## Assignment → report

1. Confirm templates/assignment.md: family run, study/learner/source policy, base/all five unlocks, objectives/extensions/literacy, family plan, complete catalogue and relevant original historical references under AGENTS.md, per-stage prior/planning boundaries, exact owned files and exclusive report path. Get `python3 -m lesson_factory.family_cli binding --run RUN --role ROLE` before reading. Missing required content, binding or tools needed for family_cli validation are blockers, not imagined passes. Browser inspection is not part of authoring or content review: do not perform browser discovery, walkthroughs, screenshots or browser skip/waiver checklists. Continue the required Markdown, semantic, linguistic and assessment audits regardless of browser availability. This supersedes older mandatory or optional browser assignments and browser-only blocked states. A parser pass alone is still insufficient without the actual assigned content audit. Renderer/UI testing is separate engineering work; never claim it as performed by a content review.
2. Read actual five briefs and all source/assigned locale stages. Scan all catalogue pages, then independently verify selected relevant historical originals and their dependencies under AGENTS.md; do not exhaustively reread unrelated banks or all translated histories. Use pinned source history for source roles and additionally the assigned learner locale for language roles. Catalogue claims alone never prove a prerequisite, and future/planning records never become earlier teaching. Use compact catalogue/context views and bounded original reads, not a full minified context dump; never rewrite contexts. Run `family_cli check --run RUN --locale CODE` and record exact result. Lens-specific content checks are required, redundant full tooling suites are not.
3. Source reviewers own reports only. Locale experts may edit all five members/notes only in their locale and reread after repairs. Disclose substantive authored meaning/context/assessment changes: those units and dependencies require a different genuine bilingual verifier, using the existing role and current binding. The original editor cannot call its own rewrite independently checked. Deterministic typo/format repairs can use the existing scoped recheck; uncertain impact requires fuller review. Reuse unaffected evidence only under the procedure below, not a second complete audit by default. Compare start/end bindings; unexpected writers require inspection. Findings specify stage, location, evidence, plausible learner failure, minimal repair and resolution. Separate actual correctness/scope/grading/format blockers from equally sound stylistic alternatives. Investigate precise factual disagreements instead of repeated votes.
4. Fill templates/family-review.json with exactly five stages. For assessment/language, each stage.question_checks contains every stage question ID, status, rationale and meaningful nonempty answer/alternatives/teaching_page evidence. Solve/challenge every item; do not paste keys or boilerplate as evidence. This is a compact source-key-visible audit, not hidden reasoning or blind testing. Pedagogy records stage-local lexical/prerequisite/scaffolding evidence; format records diagnostics/identity/target/audio checks.
5. After reviewed edits, obtain binding again and write actual approved/rejected report with real Task/Ensemble session identity, concrete checks and stage findings. Source binding includes five briefs/pairs/context, language all five localized pairs; final all locales/findings/prior reports. If session ID unavailable, request actual metadata, never invent it. Save outside accepted reviews/; coordinator alone submits `family_cli review --run RUN --role ROLE --file PATH`. Preserve rejected revisions before replacements.

If mandatory files, a valid binding or actual reviewer-session metadata cannot be obtained, return a non-review blocked message identifying missing inputs, attempted checks and affected stages; do not fabricate or submit family-review.json. A content defect in an otherwise inspectable bound family instead receives an honest rejected report. The coordinator records operational blockage and stops affected workers; a blocked message never counts as approval.

Use progress-aware, finite content repair rather than a blanket two-round stop. Preserve existing counts and rejected evidence on resume. The current assignment permits up to six substantive coordinated repair passes per affected source or locale review scope; group known repairs before rereview. Continue while identified defects are being resolved or new integration findings are actionable. A newly discovered isolated typo, heading/label error or deterministic formatting correction can be repaired in one targeted integration pass even after those six passes; it must receive genuine current-bound reapproval from the affected independent reviewer and renewed final sign-off. This exception does not reopen source meaning, grading, prerequisites or unrelated style. If the same defect remains after two attempted fixes, seek one evidence-focused independent adjudication instead of repeating the same edit. Stop on three unchanged checks of that defect, a failed targeted integration repair, unresolved substantive disagreement, missing evidence or six nonlocal passes without completion. Record defect IDs, affected scope, counts and actual progress in existing findings/handoff evidence; do not reset counts through new sessions, invent approval, or purchase translations to solve review disagreements. This replaces older default-two-round assignments, including browser-era recovery handoffs, without changing paid budgets. A genuinely explicit lower operator cap still requires an explicit operator update; retain that earlier instruction and record the new scope rather than silently treating it as a default.

The CLI can enforce stage/ID coverage and evidence fields, not genuine reasoning or meaningful truth. Coordinator inspects evidence and removes placeholders. Approval needs resolved blockers; rejection is useful evidence, not a workflow failure to conceal.

## Invalidation

| Change | Required action |
| --- | --- |
| Any source member or stage brief | Three fresh current-bound source reports, ten reconciled current-bound locale reports, final; scope actual rereview to the verified change impact below. |
| One localized member | Fresh current-bound locale report and final; scope actual rereview to the verified change impact below. |
| Review/shared finding | New final binding; affected experts inspect substantive changes. |
| Frozen context/reference/history | Stop drift; never manually recompute hashes. |
| Prompt/tool implementation | Follow authoring-tooling, retest affected content and actual rereview; bindings do not certify implementation bytes. |

Before grouped repairs, ensure the exact reviewed revision or a trustworthy comparison base remains retrievable through existing file/version/session evidence; preserving reports alone is insufficient for a differential recheck. If prior content cannot be recovered, use the full-rereview fallback. Initial reviews cover the full assigned family and every required question. For a subsequent repair, the genuine reviewer compares actual previous/current content and complete bindings, records changed stage/page/question IDs and dependencies, and reruns current family validation. A verified isolated typo needs its passage and affected items rechecked; grammar, answer, accepted-form, prerequisite, scope or shared-meaning changes require all dependent stages/items/locales. Prior evidence may be referenced only for demonstrably unchanged content and context. Assessment/language reports still account for every question, explaining which evidence was retained versus newly checked. Missing prior bytes/evidence or uncertain impact requires full rereview. A reviewer—not the coordinator—issues the fresh report under its actual session identity; never patch hashes in an old report or pretend an unchanged item was solved again.

## Shared findings → publication

Experts broadcast stage/page/question IDs, actual defect/evidence, repair and affected skills/locales. Coordinator maintains shared-findings, merges duplicates and gets ten actual checked/fixed/not-applicable acknowledgments. Source corrections need all three source rechecks too. Completed experts require concrete reactivation; stopped ones new actual review. No fabricated peer acknowledgment, isolated target fork or majority-rule truth.

Coordinator performs integration sign-off across all eleven trees/notes, the family plan, coverage, exact report bindings and acknowledgments. Reference actual specialist reports instead of repeating their item-by-item linguistic audit; inspect affected content when shared findings, suspicious repairs, contradictions or incomplete evidence warrant it. Stop every writer; obtain final binding, author actual final report using templates/family-review.json, submit final, then `python3 -m lesson_factory.family_cli finalize --run RUN`. Binding alone is not approval. Confirm returned immutable family_packs/<study>/<base6> manifest/registry, all5stage identities,11locales,25–50questions/stage and125–250family. No partial bundle or invented manifests.

Repeated finalize verifies registered immutable bundle or follows exact interrupted publication recovery. Never manually move trees/fabricate rows, edit finalized files, delete persistent lock files or rehash old evidence. Advisory locks cover cooperating commands, not arbitrary editors. Report actual checks and missing native/app/media verification; parser success is not learner mastery.
